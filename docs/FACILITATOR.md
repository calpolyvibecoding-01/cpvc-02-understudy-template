## The UI lesson, without a design lecture

Show the answer before supporting detail. Use type and spacing before more boxes.
Inspect a phone screenshot; name one weakness and fix it. One reference is enough
in open build. Borrow a rule, not somebody's full interface. A reveal may clarify
evidence; perpetual movement does not. Keep controls usable without motion.

[Signal's four-minute tour and references](https://github.com/calpolyvibecoding-01/cpvc-02-signal/blob/main/docs/DEMO_WALKTHROUGH.md)
are for your rehearsal or open build, not four extra minutes in the guided block.
The example's comparison, constellation, persistence and export are a stretch.

Other clinic prompts: “Make the header better” tests whether the reader rule
sticks without a reminder. “Improve the missing-file message and give a recovery
action” tests reliability. Restore the correct filename and verify normal loading
before merging. Keep each experiment to one change and one observable test.

## Recovery

| Stuck on | First move |
| --- | --- |
| Repo access or account setup | Officer table or Lane C. No stage-side account debugging. |
| Pages 404 | Check main/root settings and Actions. Refresh after success. |
| Extra changed files | Ask the agent to undo only its out-of-scope edits; preserve your brief. |
| Unsupported claim | Remove it or turn it into a question. Do not alter the fixture to fit it. |
| No preview in the tool | Officer-assisted local web server or reviewed branch preview. Do not merge unseen UI as a completed visual check. |
| Deliberately broken filename | Restore it, reload normal data, then review and ship. |

Afterward record attendance, submitted links, merged PRs, Lane C count and the main
failure point as aggregates, not member records. Use them to adjust the next session.
